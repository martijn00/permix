Permix is a small, framework-agnostic permissions library. You declare a typed schema once, assign rules with `setup()`, and check with dot-path strings. The same definition drives UI, HTTP middleware, and full-stack adapters.

## Three steps

1. **Define** the vocabulary — `createPermix<{ post: ['read', 'update'] }>()`
2. **Setup** rules for the current user or request — booleans or `(data) => boolean`
3. **Check** — `permix.check('post.read')`

Client `check` is UX. The server (middleware, server function, Route Handler, or provider adapter) is the enforcement boundary. See [Security](/docs/guide/security).

```ts twoslash
import { createPermix } from 'permix'

const permix = createPermix<{
  post: ['read']
}>()

permix.setup({
  post: {
    read: true,
  },
})

const canReadPost = permix.check('post.read') // true
```

## A fuller example

```ts twoslash
import { createPermix } from 'permix'

interface User {
  id: string
  role: 'editor' | 'user'
}

interface Post {
  id: string
  title: string
  authorId: string
  published: boolean
}

interface Comment {
  id: string
  content: string
  authorId: string
}

type PermissionsDefinition = {
  post: [
    { name: 'create'; type: Post },
    { name: 'read'; type: Post },
    { name: 'update'; type: Post },
    { name: 'delete'; type: Post },
  ]
  comment: [
    { name: 'create'; type: Comment },
    { name: 'read'; type: Comment },
    { name: 'update'; type: Comment },
  ]
}

const permix = createPermix<PermissionsDefinition>()

const editorPermissions = permix.template({
  post: {
    create: true,
    read: true,
    update: (post) => !post?.published,
    delete: (post) => !post?.published,
  },
  comment: {
    create: false,
    read: true,
    update: false,
  },
})

const userPermissions = permix.template(({ id: userId }: User) => ({
  post: {
    create: false,
    read: true,
    update: false,
    delete: false,
  },
  comment: {
    create: true,
    read: true,
    update: (comment) => comment?.authorId === userId,
  },
}))

async function getUser() {
  return {
    id: '1',
    role: 'editor' as const,
  }
}

async function setupPermix() {
  const user = await getUser()
  const permissionsMap = {
    editor: () => editorPermissions(),
    user: () => userPermissions(user),
  }

  permix.setup(permissionsMap[user.role]())
}

setupPermix()

const canCreatePost = permix.check('post.create')

async function getComment() {
  return {
    id: '1',
    content: 'Hello, world!',
    authorId: '1',
  }
}

const comment = await getComment()

const canUpdateComment = permix.check('comment.update', comment)
```

## Why Permix

- Native TypeScript (5.9, 6, and 7) without a second type layer
- One schema for the whole app and monorepo
- Zero runtime dependencies in core
- Built-in SSR via [dehydrate / hydrate](/docs/guide/hydration)
- Relationship-based rules with closures — [ReBAC](/docs/guide/rebac)
- Adapters for UI, full-stack, HTTP/RPC, and identity providers

Unsure which adapter to import? [Choose an adapter](/docs/guide/choose-adapter).

## Background

Permix started from the limits of `if (user.role === 'admin')` and of [CASL](https://casl.js.org) in TypeScript-heavy apps. The shape of `setup` / `check` was inspired by [Web Dev Simplified's permissions walkthrough](https://www.youtube.com/watch?v=5GG-VUvruzE). Feature comparison with CASL: [Comparison](/docs/comparison).
